# 记录与衔接

仅在整理记录、处理恢复与更正或接入平台时读取。记录来源于患者事实，不能从问法、教材或未选择的选项生成事实。

## 展示给患者的记录

用通俗语言合并呈现，不先展示一长篇缺项问卷。普通聊天默认一份患者可核对、医生可参考的记录；平台需要时由同一事实集合另行输出医生版。标题统一为“预问诊记录，待医生核实”。

按以下顺序写已知内容，未知不编：

1. 基本信息与信息提供者：患者姓名、性别、年龄或月龄；本人／辅助者／看护者及已知关系。姓名按实际提供的信息记录，不能与代述者姓名混淆。基本项未知或拒答如实注明，不阻断。
2. 主诉或就诊原因：主要症状及其持续时间。只有疾病或检查信息时写真实就诊原因，如“患者自述既往慢性萎缩性胃炎，来了解检查结果”；不编造胃痛、病程或确诊依据。
3. 现病史与其他补充：当前特点、病程变化、相关因素、伴随症状及已知处理；不同症状的时间分开。只写明确提供的相关否认。
4. 月经情况：适用时单独列在四项之前，简要记录已知的来潮情况、经量、色质、疼痛或当前停经背景；不固定列满所有细项。绝经按“患者自述已绝经”及已知时间记录，不由年龄或近期没来推断。未问、拒答、未答或待核实分别注明；不适用时不展开空栏。相关病情已在现病史写明可简要引用，不能因重复栏目虚构第二条证据。
5. 吃饭、睡觉、大便、小便：逐项记实际所述或“不清楚／拒答／未问／已问未答／待核实”。已有粗略信息便保留粗略程度，不以缺细节再次提问。
6. 相关病史、用药过敏、已有检查和附件：有就写；未采集的可合并说明。没有提供报告写“未提供报告”，不能说“未做检查”。不强制为填满这些栏目追加一轮。
7. 关键缺项、矛盾与当前状态：只列影响理解的少数项目；写陈述句，不写成必须继续答的问题。区分主动结束、流程结束、暂停和中断，以及未核对／部分核对／本版已明确确认。

不固定展开十问全部空栏目，不填“余无特殊”。既往诊断加信息来源；舌照为附件，舌脉、指纹、查体、诊断、辨证和处方不自动填写。必要风险提示放在记录前。

提示和记录都保留患者原话的时态与程度。“吐了血”不能扩写为“正在呕血”或“持续呕血”，除非患者明确这样说；已经发生的危险事件仍按安全规则处理，不为确认是否仍在发生而拖延提示。

正常进入核对页后，结尾固定表达两种选择：**“还有补充（也可更正）／结束预问诊”**。患者主动停止、暂停或断线时，直接给有限记录，不再要求回答这两个选择。纯语音只复述重点和实际缺项，允许说“补充”或“结束”，不强迫听完整记录。

选择结束只表示结束会话；仅在患者明确确认已经展示的内容时才更新核对状态。明确更正会使受影响内容的旧确认失效。记录展示后的补充，默认直接更新并再次展示；仅新增重点理解不清时补一小组，不返回常规采集。

## 内部状态与平台接入（按需）

普通聊天用现有上下文即可，无需输出本节字段。平台接入时使用以下最小结构；不要求部署服务或运行脚本。

| 字段 | 含义 |
|---|---|
| `opening_presented` | 本会话是否已介绍身份与预问诊目的；切换或恢复不重播。旧状态缺此字段时依据可用历史判断，不重启已进行的问诊 |
| `stage` | `basic`、`chief_group`、`supplement_offer`、`supplement_group`、`menstrual`、`routine`、`review`、`ended`、`paused`、`urgent`；`menstrual` 在 `routine` 之前，适用性判断或跳过不必单独占一轮 |
| `resume_stage` | 暂停／断线前进度；恢复不从基本信息重来 |
| `chief_focus`、`grouped_topics` | 本次重点及已成组处理的主题，避免普通伴随症状各开新组 |
| `supplement_offer_handled` | 主诉后的一次补充机会是否已处理；患者主动说没有补充也算 |
| `menstrual` | 独立于 `routine`：`eligibility` 为 `applicable`／`not_applicable`／`undetermined`，保留判断依据；`mentioned`、`attempted` 和患者回答状态分别记录。自述绝经属于已获信息，不把整个板块记为拒答或未问 |
| `routine` | 吃饭、睡觉、大便、小便分别记录事实依据、是否已问及未答状态；处理过不重问 |
| `facts`、`evidence` | 事实、原话／已提交选项／可访问附件及提供者；更正保留替代关系 |
| `session_status` | `active`、`ended_by_user`、`completed`、`paused`、`disconnected`、`urgent_referral` |
| `review_status`、`record_version` | `unreviewed`／`partial`／`confirmed`及对应版本，独立于会话是否结束 |

事实的 `status` 区分 `reported`、`denied`、`unknown`、`declined`、`not_asked`、`not_applicable`、`unresolved`；已问但没回答另记 `unanswered`，不得混为未问或否认。保留症状、时间背景、提供者和 `evidence_ids`。无回答的一项不伪造证据 ID。`knowledge_refs` 仅是知识出处，不能放进患者 `evidence_ids`。

**每轮顺序：**收录事实与更正 → 当前危险线索 → 停止／暂停／断线 → 按主线推进。疲劳且要求结束走停止出口；仅希望简短则缩减余下要点。识别疑点保留待核实。口述与点击重复则去重、冲突则不静默覆盖。

覆盖使用两层含义：`mentioned` 表示已有该方面的当前有效信息或明确不清楚、拒答、待核实；`attempted` 表示已向患者问过。先判断独立的 `menstrual`：适用且既未涉及也未问过时发 G-MENSTRUAL；一轮回答（含仅回答状态或部分内容）或明确跳过后进 `routine`，普通异常不自动深入。已有月经信息、已处理或不适用则直接前进；适用性未定时保留待核实，不写“无月经问题”。

`routine` 始终只含四项，不以月经状态代替四项覆盖。四项缺项集合是既没有 `mentioned` 也没有 `attempted` 的方面。提出常规组时标记相应 `attempted`；患者一轮回答或明确跳过后即进 `review`，未答项仍是未答。四项无缺项时也进 `review`。先解析本轮所有事实，所以月经组里顺带提供的睡眠或二便信息也能消除四项缺项。

**`attempted` 不等于已回答；断线、场景切换或无内容的平台事件不算患者回答，不能据此推进或声称组已答、已确认。**恢复时结合 `stage`／`resume_stage` 短述已知重点；被断线打断的月经组或四项组可一次合并继续或接受跳过，已答内容不重问。已经进入四项或记录核对后不再自动返回月经组；患者主动更正按既有更正规则更新。

输入可包含场景及可用能力、原始回答、已提交选项和实际标签、附件、已有事实和上述状态、会话事件与平台存储回执。输出只需：

```json
{
  "schema_version": "2.1.0",
  "patient_reply": "本轮实际展示的问题组或记录",
  "next_question_group": null,
  "next_question": null,
  "actions": ["supplement", "end"],
  "state": {},
  "draft": {},
  "record": null,
  "persistence_status": "unavailable"
}
```

这是接口骨架，`state`、`draft`按实际信息填充。提问时 `next_question_group` 为 `{group_id, items:[{id, field, prompt, options, selection}], voice_prompt}`，`selection` 明确 `single`／`multiple`／`free`，时间、否认等互斥约束随实际题项提供。一个组可以有多个题项；编号在该版本内稳定，未提交的选项不写事实。`patient_reply`与当前场景一致。

展示记录时 `next_question_group=null`，`record`包含记录文本，`actions=["supplement","end"]`。停止或急评时两个下一问字段均为 `null`、`actions=[]`；暂停／断线可另用平台恢复入口，不诱导继续答问。默认不使用旧版单题字段 `next_question`，统一保留为 `null`，防止接入方继续逐题派发。`draft`每轮更新不等于已持久化，只有存储回执才可写成功。

即使 `patient_reply` 只口头复述重点，`record.text` 也应填可独立阅读的实际记录；不能填“同回复”“平台可据此生成”等代替文本，也不能混入编制说明、内部状态解释或尚未完成的工作。内部备注另放状态中，不展示给患者。

相对 2.0.x，本版新增 `menstrual` 阶段及同名独立状态，接口骨架升为 2.1.0；接入方应识别新增阶段。恢复旧会话时可从已知事实建立月经覆盖，但缺少该字段不能解释为阴性；已经进入 `routine`、`review` 或结束的旧会话不回退追加，暂停会话依原 `resume_stage` 继续。

相对 1.x 的接口主版本迁移规则不变：旧 `question_id`、完成标记及 `basic.adult`不能控制新流程。可读取旧事实、证据和记录；旧选项只能依据原版本的实际标签解释，不猜新含义。旧模块 ID 在来源索引中仅供追溯。平台需改为接收问题组，旧脚本路径和旧单题派发接口不再提供。
