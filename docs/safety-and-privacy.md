# 医疗安全与隐私

## 用途边界

系统只负责就诊前信息收集、动态追问和摘要整理。输出必须标记“待医务人员确认”，不得声称完成诊断、处方或急救判断。

## 红旗优先

> 当前状态：本节的确定性安全层是设计要求，**尚未实现**。现阶段危险线索由 `tcm-preconsultation` Skill 中的提示承担（由 LLM 执行，出现急症线索时暂停常规询问并提示联系急救或尽快急诊），只是最低限度提醒，不构成完整分诊。

确定性安全层在每次患者回答后先运行。命中自伤/他伤意图、意识障碍、严重胸痛、明显呼吸困难、大出血等信号时：

1. 停止普通预问诊问题；
2. 显示明确、简短的紧急升级提示；
3. 鼓励联系当地急救服务、尽快前往急诊并寻求身边可信任人员帮助；
4. 记录规则 ID，不在普通日志中复制患者完整原文；
5. 不让 LLM 降低风险等级或用安慰性措辞替代升级提示。

关键词原型只用于黑客松演示，不能作为临床部署的充分依据。正式试用前必须由医疗、隐私和合规专家评估。

## 数据最小化

- 预问诊开场会请患者说出姓名、性别、年龄和主要不适（`tcm-preconsultation` Skill）。每一项都可以不答，姓名未提供不影响问诊；系统不核验身份，只按患者实际说的内容记录，所以只给称呼或化名也可以；
- 不询问身份证号、电话号码、住址等其他身份信息；
- 只采集预问诊所需信息；
- 会话用随机 ID 标识，不由身份信息生成；
- 演示只使用虚构数据；
- 问诊文字记录（患者原话、助手回复、小结，含患者提供的姓名或称呼）默认写在本机 `DOCTOR_RECORD_DIR`（文件 600、目录 700），供医生端和阶段三 judge 读取，不上传云端；`DOCTOR_RECORD=0` 可停写；
- 目标是日志只记版本、延迟、规则 ID 和错误码。当前实现尚未做到：LiveTalking 运行日志 `app.log` 会记下每轮患者文字和助手回复，便于排障，正式试用前需关闭或脱敏；
- 实时问诊的音频只在内存中用于识别，不落盘；实时问诊目前不采集摄像头画面。阶段三 face_body 只离线处理事先录好的视频，`analyze` 只输出数值、不存图像；
- 患者可以不授权麦克风，直接打字问诊。阶段三 judge 在问诊结束后用本机模型读文字记录，为医生端生成「重点」提示，目前没有让患者单独关闭的开关，只能整体停用（停掉 judge 服务或停写问诊记录）。

## 本地优先

默认推理和数据处理在 DGX Spark 或院内受控设备完成。任何外部网络或云端能力必须：显式开启、清楚告知数据类型、取得授权、最小化传输并提供关闭方法。

## 情感识别限制

情感模型输出是易受文化、个体、光照和噪声影响的弱信号。必须有置信度、模型版本和 `unknown` 状态，不得用于诊断精神疾病、自动拒诊、排序医疗资源或覆盖患者自述。

## 漏洞报告

请不要在公开 Issue 中发布患者数据、密钥或可被立即利用的安全细节。仓库管理员应在 GitHub Security Advisories 或私密渠道接收报告。
