# 产品构想与范围

## 一句话价值

探索利用 DGX Spark 本地算力和大模型，让预问诊问题能够随科室和患者回答动态变化，为医生提供比固定表单更完整的信息。

## 目标用户

- 患者：获得比固定表单更自然、更有针对性的预问诊体验；
- 医生/分诊人员：在正式接诊前获得结构化且来源清晰的信息；
- 医疗机构：探索敏感数据本地处理和本地模型部署方式。

## 三阶段构想

### 第一阶段：动态文字预问诊

基于预设树形步骤以及大模型实时运算，在患者逐个回答时动态修正后续问题，帮助医生获取关键信息。

### 第二阶段：多模态动态预问诊

在第一阶段基础上加入语音生成或动态头像，使交互不局限于文字。

### 第三阶段：情感识别问诊

在第二阶段基础上加入语音情感和面部表情识别，将不确定的情绪趋势作为医生辅助信息。

## 当前项目边界

阶段二、三已实现，并部署在 DGX Spark 上运行：

- 阶段二（`apps/multimodal/`）：本地数字人、ASR/TTS/LLM，OpenClaw 预问诊 agent（`tcm-preconsultation` Skill），患者端预问诊页与医生工作台；
- 阶段三（`apps/emotion/`）：问诊结束后的对话重点判断 `judge/`（常驻服务，给医生工作台「重点」页签供数）；面部与身体观察 `face_body/` 离线处理视频文件，也统计患者页可选摄像头观察的关键点数值（问诊结束后给医生工作台逐条回答的同期观察）。

文字预问诊暂由上述 OpenClaw agent 与 Skill 承担，患者页可全程打字。确定性红旗规则层已有设计（见 [医疗安全与隐私](safety-and-privacy.md)），尚未实现。具体科室、问题树、接口、数据结构和验收案例仍由各阶段负责人通过 Issue 提案后确定。

## 长期非目标

- 替代医生完成疾病诊断；
- 提供处方或药物剂量建议；
- 替代急救服务或正式分诊制度；
- 未经审核直接写入正式电子病历；
- 使用情感识别结果自动诊断、拒诊或分配医疗资源。
