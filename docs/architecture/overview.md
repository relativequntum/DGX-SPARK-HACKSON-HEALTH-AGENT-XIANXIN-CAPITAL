# 架构原则与待决事项

本文件记录项目初始化阶段明确的原则；阶段二、三已按这些原则落地（见「当前实现」），其余待裁决事项仍以 Issue 结论为准。

## 已明确原则

1. **本地优先**：优先利用 DGX Spark 在本地进行模型推理和敏感数据处理；
2. **安全优先**：医疗安全规则不能依赖大模型自行遵守；
3. **结构化协作**：阶段之间应通过清晰、版本化的契约协作；
4. **模型可替换**：业务逻辑不应永久绑定单一模型或推理框架；
5. **可降级**：高级能力不可用时，未来系统仍应有安全、明确的降级路径；
6. **隐私最小化**：只采集必要数据，默认不保存原始音视频和直接身份信息。

## 当前实现

- **阶段二**（`apps/multimodal/`）：LiveTalking 数字人 + WebRTC（经 TURN 的 TCP 中继），本地 SenseVoice 语音识别与 ChatTTS 语音合成；对话走 OpenClaw agent（`tcm-preconsultation` Skill），失败时降级到同机 llama.cpp `llama-server`（Qwen3.6-35B-A3B GGUF）；医生工作台读取本机问诊记录。已部署在 DGX Spark。
- **阶段三**（`apps/emotion/`）：`judge/` 在问诊结束后用同一个本地模型判断对话重点，给医生工作台「重点」页签供数；`face_body/` 用 MediaPipe 离线处理视频，并在问诊结束后统计患者页可选摄像头观察的关键点数值（浏览器端打点，画面不出浏览器），给医生工作台的同期观察。
- **阶段一**（`apps/text_triage/`）与 `packages/core/` 仍是预留目录；文字预问诊暂由 OpenClaw agent 与 Skill 承担。
- 原则 2 要求的确定性红旗规则层已有设计（[`docs/safety-and-privacy.md`](../safety-and-privacy.md)），尚未实现；跨阶段公共契约也尚未冻结。

## 三阶段边界

```text
阶段一：文字问诊与会话逻辑
           │
           ├── 公共契约：会话、消息、安全事件、摘要
           │
阶段二：语音、语音生成与动态头像
           │
           └── 公共契约：多模态事件与降级机制

阶段三：语音情感与面部表情信号
```

以上仅表示职责关系，不预先规定 API、数据库或框架。

## 开工前待裁决

以下事项均应创建 `[裁决]` 或 `[会签]` Issue：

- 第一阶段首批医疗场景和问题树范围；
- DGX Spark 上的本地模型及推理服务选择；
- 前后端技术栈和仓库工程结构；
- 跨阶段会话、消息、安全和情感事件格式；
- 数据存储、删除、日志和脱敏策略；
- 红旗信号的定义、专家审阅与验收方式；
- 第二、三阶段的资源预算和文字模式降级方案。

任何阶段不得仅凭本文直接开始修改公共契约；以对应 Issue 的正式结论为准。
