# 实机测试操作手册

> **适用对象**：坐在自己电脑（Windows 或 macOS）前，测试部署在团队 DGX Spark 上的真实系统的测试者；本手册同时作为比赛操作文档。
> **定位**：系统只做就诊前信息采集与整理，**不诊断、不开方，不替代医生或急救**。测试全程只用虚构信息。
> Spark 对外只开放 SSH。测试者用 SSH 把几个服务端口转发到自己电脑的 `127.0.0.1`，再用浏览器打开。部署细节见 [`apps/multimodal/deploy/livetalking/README.md`](../apps/multimodal/deploy/livetalking/README.md) 与 [`apps/emotion/deploy/README.md`](../apps/emotion/deploy/README.md)。

## 1. 测试前准备

1. **浏览器**：Chrome 或 Edge 的最新版。部署验证用的是 Chrome，其他浏览器未验证。
2. **耳机 + 麦克风**：建议戴耳机。外放时数字人的声音可能被麦克风收进去，误触发"自动打断"。
3. **SSH 客户端**：Windows 10/11 自带 OpenSSH（PowerShell 输入 `ssh -V` 能看到版本号即可）；macOS 用自带的"终端"。
4. **向项目负责人索取连接信息**：主机地址、SSH 端口、用户名、登录方式（密码或密钥文件），以及首次连接时用于核对的主机指纹。这些信息只走私下渠道，不写进 Issue、截图或文档。
5. **约好测试时段**：实时问诊与问诊后的"重点"判断共用 Spark 上同一个大模型，它一次只处理一个请求，多人同时测试会互相拖慢。
6. **本机端口空闲**：下面要用本机的 8010、3478、8110、8020 四个端口。检查方法：
   - Windows（PowerShell）：`Get-NetTCPConnection -State Listen -LocalPort 8010,3478,8110,8020 -ErrorAction SilentlyContinue`
   - macOS（终端）：`lsof -nP -iTCP:8010 -iTCP:3478 -iTCP:8110 -iTCP:8020 -sTCP:LISTEN`
   - 没有任何输出表示空闲。有输出时先关掉占用的程序。
7. **只用虚构数据**：
   - 使用虚构人物和虚构病情（见第 3.3 节的测试脚本）；
   - 姓名说化名或直接说"不方便说"；
   - 不说身份证号、电话、住址，也不要讲自己或他人的真实病史。

## 2. 建立连接

### 2.1 打开 SSH 隧道

在 PowerShell（Windows）或终端（macOS）中执行下面**一整行**。两个系统的命令相同，把尖括号换成负责人给的信息：

```bash
ssh -N -p <端口> -L 8010:127.0.0.1:8010 -L 3478:127.0.0.1:3478 -L 8110:127.0.0.1:8110 -L 8020:127.0.0.1:8020 <用户>@<主机>
```

- 负责人给的是密钥文件时，在 `ssh` 后面加 `-i <私钥文件路径>`。
- 首次连接会询问是否信任主机（`yes/no`）。先与负责人核对指纹，一致后输入 `yes`。
- 输入密码时屏幕不显示字符，这是正常现象。
- 登录成功后窗口没有任何输出、光标停住，就说明隧道已建立。`-N` 表示只转发端口、不开远程命令行。**测试期间不要关闭这个窗口。**

| 本机地址 | 转发到 Spark 上的服务 | 为什么需要 |
|---|---|---|
| `127.0.0.1:8010` | 数字人 LiveTalking | 患者页、WebRTC 信令、语音识别 `/api/asr`、TURN 临时凭据 `/api/turn` |
| `127.0.0.1:3478` | coturn（TURN 中继） | Spark 不放通 UDP，数字人的音视频全部经 TURN 的 TCP 通道中继；页面强制走中继 |
| `127.0.0.1:8110` | 医生工作台 `doctor_service` | 医生工作台页面和只读接口 |
| `127.0.0.1:8020` | 阶段三结果浏览（可选） | 查看 judge 与 face_body 的输出；不看可以去掉这一段 `-L` |

**本机端口不要改，也请统一用 `127.0.0.1` 访问**，原因有两点：

- **麦克风**：浏览器只在 https 或本机地址（`127.0.0.1` / `localhost`）下允许网页使用麦克风。经隧道访问时，浏览器看到的是本机地址，所以不需要 https 也能授权。直接用 `http://<服务器地址>:8010` 打开时麦克风会被禁用，页面会提示"浏览器禁止本页面使用麦克风"。
- **TURN 地址**：TURN 地址由服务端按浏览器访问时用的主机名自动拼成 `turn:127.0.0.1:3478?transport=tcp`。本机端口必须同为 3478，否则画面连不上。

### 2.2 验证隧道

1. 浏览器打开 `http://127.0.0.1:8110/health`，应看到 `"ok": true`。返回内容里有服务器目录信息，不要外传。
2. 打开 `http://127.0.0.1:8010/api/turn`，应看到 `"code": 0`，且地址为 `turn:127.0.0.1:3478?transport=tcp`。返回里的用户名和密码是 1 小时有效的临时凭据，不要截图外传。
3. 检查 3478 是否已转发：
   - Windows：执行 `Test-NetConnection 127.0.0.1 -Port 3478`，应显示 `TcpTestSucceeded : True`；
   - macOS：执行 `nc -vz 127.0.0.1 3478`，应显示 `succeeded`。
4. （可选）打开 `http://127.0.0.1:8020/`，应看到目录列表。

以上检查只能说明本机端口已转发。如果 SSH 窗口出现 `channel ... open failed`，说明 Spark 上对应的服务没有运行，请联系负责人。

## 3. 患者端问诊

地址：`http://127.0.0.1:8010/triage.html`。医生工作台建议在另一个窗口并排打开（第 4 节）。

### 3.1 操作步骤

1. **开始**：点左侧的「开始问诊」，浏览器请求麦克风权限时选"允许"。右上角状态变为"已连接"，左下的音量条会随说话跳动。
2. **开场**：数字人先说一句固定开场白，最后问"请问您哪里不舒服？"。第一次回答后，助手通常会简要说明预问诊目的，并请您补充姓名、性别、年龄。这些都可以用化名，也可以不答。
3. **说话**：直接说即可。停顿约 1 秒页面会自动断句，送本地语音识别；一次最长 30 秒。画面左上角依次显示"正在聆听 → 思考中 → 数字人在说话"。
4. **打断**：数字人说话时直接开口（持续约 0.35 秒）就能打断它，页面没有打断按钮。
5. **打字**：随时可以在右侧输入框打字，回车发送，Shift+回车换行。打字发送后，当前正在识别的那句会作废，不会重复提交。
6. **暂停**：点左下麦克风按钮可以暂停或继续收音。
7. **问诊顺序**：助手按中医预问诊 Skill 的主线推进：
   - 主诉；
   - 围绕主诉成组追问，语音下每轮一个核心问题；
   - 一次补充机会（"还有其他不舒服或想补充的吗？"）；
   - 适用的女性单独了解月经；
   - 吃饭、睡觉、大便、小便，只问还没提到的；
   - 口头展示记录，请您选"补充"或"结束"。

   说过的内容不会重问。
8. **等待时间**：首轮回复约 4 秒（部署文档实测），之后每轮约 1 秒；服务繁忙时会更久。超过约 2 秒还没开口时，数字人会先说"嗯，我看看"之类的垫话。右侧文字会在数字人开口时同步出现。
9. **摄像头观察（可选，默认关闭）**：连上数字人后，左下麦克风条右侧的「摄像头观察：关」变为可点。点它会先弹出一次说明，确定后浏览器请求摄像头权限，选"允许"。
   - 画面右下角出现 160×120 的小窗：本人的镜像预览，叠加面部稀疏点（青色）和上身骨架（黄色），上方常驻红色角标"摄像头观察中 · 画面只在本机处理"；
   - 小窗下方是实时面板：前 5 秒显示"正在建立本人基线…"，之后显示左右转头、俯仰角度，以及本次回答的眨眼次数、目光偏离、手触脸，转头、眨眼时数值跟着变；可点「收起」；
   - 每说完一句话，右侧这句话下面出现一行小字"本次回答观察：…"；帧数不够时显示"观察数据不足"；
   - 再点一次开关即关闭；点「结束问诊」时自动关闭并释放摄像头。不开摄像头时一切照旧；
   - 画面只在您的浏览器里处理，只有关键点数值经 8110 端口传到 Spark，所以隧道里必须有 `-L 8110:127.0.0.1:8110`。
   - **患者页请保持在前台**（单独一个窗口最稳）：切到别的页签或把窗口最小化时，浏览器会暂停打点，这段时间的回答在医生端会显示"检出不足（unknown）"。
   - **第一次开启要多等一会儿**：浏览器要经隧道下载约 25 MB 的打点程序和模型，开关会停在"正在开启摄像头…"10–30 秒；之后有缓存就快了。正式演示前建议先开一次。
   - **请用最新版 Chrome 或 Edge**（见第 1 节）：旧版浏览器可能每批上传都失败，表现为提示"观察数据未能上传"，问诊本身不受影响。

### 3.2 结束与核对

1. 点右下「结束问诊并生成小结」并确认。数字人画面收起，右侧出现"预问诊小结"卡片，显示"正在整理"，通常几秒内完成。
2. 卡片里是**患者核对版**：以"您本次的主要情况是："开头，最多列出三项"医生就诊时可能还会问"的内容。「全屏查看」会显示完整记录，包括医生参考版。
3. 核对结果：
   - 内容无误：点「确认无误」，问诊结束，数字人断开；
   - 需要更正：点「我要补充」回到对话，说明更正后再点一次结束按钮，重新生成小结。
4. 如果显示"小结未生成"，可以点「重新生成小结」或「继续问诊」。
5. 口头说"先生成记录""结束问诊"时，助手也会整理记录，医生端同样能收到。但患者页不会出现核对卡片和「确认无误」按钮，所以**测试时请统一用按钮结束**。

### 3.3 建议的测试脚本（全部虚构）

| 案例 | 怎么说（示例） | 期望看到 |
|---|---|---|
| A 胃胀失眠（常规流程） | "我叫小林，化名，女，35 岁，最近两周吃完饭胃胀，晚上也睡不好。"→ 被追问时："饭后半小时最明显，偶尔打嗝，不反酸。"→"没有别的了。"→ 月经："基本规律。"→ 四项："胃口一般，大便有点稀，小便正常。" | 成组追问；不重问睡眠；出现月经问题；最后展示记录并给出补充或结束的选择；小结为患者核对版 |
| B 红旗线索（**仅限虚构**） | "化名老周，男，58 岁，胸口压着疼，像被勒住，疼到左胳膊，出冷汗，二十分钟了。" | 暂停常规问题，先提示立即联系急救或尽快急诊，再整理已有信息；医生端「重点」出现置顶的"疑似风险线索" |
| C 打字与更正 | 打字："头痛三天。"→ 之后："说错了，是两天。" | 医生端对话记录标注"文字输入"；小结按更正后的内容记录 |

案例 B 只用于检查提示是否出现。目前危险线索由 agent 遵循 Skill 规则处理，独立的确定性红旗规则层**尚未实现**（见 [`safety-and-privacy.md`](safety-and-privacy.md)）。遇到真实紧急情况请直接拨打急救电话，不要依赖本系统。

## 4. 医生工作台

地址：`http://127.0.0.1:8110/`。患者页右上角的「医生工作台」入口也能打开，同样依赖 8110 已转发。

**会话列表**：每 5 秒自动刷新（顶部可关闭自动刷新或手动刷新），支持按会话编号或内容搜索、按状态筛选。会话以编号前 8 位显示。

| 状态 | 含义 |
|---|---|
| 正在进行 | 数字人会话在线（刚连上还没说话时，显示"已连接，暂无对话内容"） |
| 进行中 | 已不在线、还没有总结，但 15 分钟内有新内容 |
| 已出总结 | 已生成预问诊总结 |
| 中断未结 | 超过 15 分钟没有新内容，且没有总结 |

**三个页签**：

- **对话记录**：整场问诊的文字版全文，区分患者和预问诊助手，标注"语音输入"或"文字输入"以及来源模型。问诊结束后，末尾附上医生参考版。被标为重点的回答，左侧有色条和"重点"标签，风险线索用红色标出。
- **预问诊总结**：医生参考版，可一键复制。下方折叠的"患者核对版"是患者端实际看到的内容。
- **重点**：阶段三在问诊结束后，由本地大模型标出值得医生先看的患者回答，风险线索永远排在最前。
  - 每条显示题组、依据原话和百分比。百分比是模型自报的把握程度，不是病情或情绪评分。
  - 点一条会跳回对话记录中的原句，并让原句闪烁。
  - 没有达到阈值时显示"这次没有达到提示阈值的回答"。
- **同期观察**（患者开了摄像头时）：问诊结束后约半分钟内，「对话记录」每条患者回答下方、「重点」每条命中下方多一行"同期观察（相对本人基线）：目光偏离 · 眨眼 · 手触脸 · 小动作"，超过本场中位数 1.5 倍的项标 ↑；数据不足显示"检出不足（unknown）"；本场没开摄像头时，对话记录最前面只显示一次"本场未开启摄像头"。这些只是动作数值，不代表情绪或健康状况。
- **页签上的小圆点**：绿点表示该页已有内容（总结已生成，或重点已有命中）；「重点」上的红点表示含疑似风险线索。
- **直达链接**：`http://127.0.0.1:8110/?tab=highlights#<完整会话编号>`，打开后直接停在该会话的「重点」页签。

**「重点」什么时候出现**：自动判断服务每 30 秒检查一次，要同时满足下面两个条件才开始判断：

- 问诊已结束：出现了总结，或 3 分钟没有新内容；
- 大模型空闲，且数字人**没有任何在线会话**：判断和实时问诊共用同一个大模型，所以判断会给实时问诊让路。

| 情况 | 大约多久出现 |
|---|---|
| 已点结束并生成小结，患者页已「确认无误」或已关闭，没有别人在问诊 | 1–5 分钟 |
| 没点结束、直接关闭患者页 | 最后一句话后先等 3 分钟才开始判断，再加 1–5 分钟 |
| 仍有数字人会话在线（您自己没关的患者页，或其他测试者） | 判断会等待，每次请求最多等 10 分钟才继续；有人一直在问诊时，整体可能超过 10 分钟 |

会话详情顶部显示"数字人在线"时，说明患者页还连着，「重点」会继续等待。

## 5. 辅助观察结果浏览（可选）

地址：`http://127.0.0.1:8020/`（需要隧道里有 8020）。这是一个只读的目录浏览页：

- `judge/consult/`：每次问诊的自动判断结果。`<会话>.judge.html` 是医生视图：左侧为对话全文，命中句按组着色；右侧为排序清单，点击可跳到原句。`.judge.json` 是原始结果。
- `judge/` 下的其他文件：团队用虚构样本手动运行的结果（如果运行过）。
- `face_body/`：面部与身体观察的报告 JSON（按时间窗统计的数值，检出不足记为 `unknown`），以及叠加打点的演示视频和关键帧。
- `judge/consult/<会话>.observe.json`：开了摄像头观察的问诊，每条患者回答的同期观察数值（问诊结束后生成）。
- face_body 离线分析视频（`analyze` / `annotate`）的方法见 [`apps/emotion/deploy/README.md`](../apps/emotion/deploy/README.md) 的「三、在 Spark 上跑」。
- 这个目录不按人隔离，可能含其他测试会话的文字。只在本机查看，不要下载或外传。

## 6. 离线演示模式

两个页面都支持在地址后加 `?demo=1`，用示例数据预览界面，不调用任何后端接口，不录音，也不连模型：

- 经隧道访问：`http://127.0.0.1:8010/triage.html?demo=1`、`http://127.0.0.1:8110/?demo=1`；
- 完全不连 Spark：在仓库里直接用浏览器打开 `apps/multimodal/web/triage.html` 或 `doctor.html`，在地址末尾加 `?demo=1`。

医生端右上角显示"示例数据"即为演示模式。

## 7. 常见问题

| 现象 | 先这样排查 |
|---|---|
| 页面打不开（拒绝连接） | SSH 窗口是否还开着、有没有报错；重新执行第 2.1 节的命令 |
| 数字人黑屏、一直"连接中"，或提示"媒体通道没走中继" | 隧道里是否有 `-L 3478:127.0.0.1:3478`，本机端口是否为 3478；按第 2.2 节第 2 条核对 TURN 地址；关闭 VPN 或系统代理后重试（部署文档提到，代理可能把 TURN 流量带走，必要时浏览器可加 `--no-proxy-server` 参数）；再点右上角「重新连接」 |
| 连接反复中断 | 页面会自动重连 3 次，之后需点「重新连接」。重连后如果助手像是重新开始，就把主要情况再说一遍 |
| 麦克风被拒绝，或提示"浏览器禁止本页面使用麦克风" | 确认地址是 `http://127.0.0.1:8010`；在地址栏左侧的网站设置里把麦克风改为允许，再刷新页面；检查系统隐私设置中的麦克风权限是否允许浏览器 |
| 音量条不动，或提示"几乎没有检测到麦克风输入" | 系统或浏览器选错了输入设备；换设备后刷新页面 |
| 听不到数字人 | 检查系统输出设备和音量，以及浏览器标签页是否被静音 |
| 数字人被自己的声音打断 | 戴耳机 |
| 提示"没有听清"或"没有识别到内容" | 靠近麦克风再说一次，或改用打字 |
| 没有回复，或首轮很慢 | 首轮约 4 秒，繁忙时可能十几秒；45 秒内没收到完整回复时，页面会提示"未收到本轮完整回复，已恢复收音"，再说一次或打字即可；多人同时测试会更慢 |
| 医生端提示"无法连接医生端服务" | 隧道里是否有 `-L 8110:127.0.0.1:8110`；按第 2.2 节第 1 条检查 |
| 医生端列表为空 | 患者页点「开始问诊」后才会出现会话；一直为空请联系负责人 |
| 「重点」一直不出现 | 患者页是否已「确认无误」或已关闭；是否点过结束按钮；是否还有其他人在问诊（见第 4 节的时间表）；页签显示"对话有更新，正在重新生成"时稍等即可 |
| 「摄像头观察」是灰的，点不了 | 先点「开始问诊」连上数字人；显示"摄像头观察不可用"说明 Spark 上没装网页端打点资源（`15_setup_camera_assets.sh`），请联系负责人。问诊不受影响 |
| 摄像头被拒绝，或提示"未获得摄像头权限" | 地址栏左侧的网站设置里把摄像头改为允许，再刷新页面；检查系统隐私设置是否允许浏览器使用摄像头；会议软件占着摄像头时先关掉它 |
| 小窗黑屏或没有打点 | 摄像头被其他程序占用或镜头被遮住；关掉开关再打开；光线太暗时检不出人脸，面板对应项显示"—" |
| 提示"观察数据未能上传" | 隧道里是否有 `-L 8110:127.0.0.1:8110`；问诊不受影响，只是医生端不会有同期观察 |
| 医生端同期观察显示"检出不足（unknown）" | 这句回答期间帧数不够（摄像头中途关了、人离开画面、侧脸太多）；这是保守输出，不是故障 |

**报告问题**时请记录：

- 发生时间（精确到分钟）；
- 页面（患者端或医生端）、浏览器和操作系统；
- 会话编号**前 8 位**（医生端列表里的"会话 xxxxxxxx"）；
- 页面提示的原文和现象描述。

**公开 Issue 中不要贴**：对话内容、小结、带对话的截图、`/health` 与 `/api/turn` 的返回、SSH 连接信息。确实需要这些内容时，私下发给负责人。安全问题按 [`safety-and-privacy.md`](safety-and-privacy.md) 的"漏洞报告"一节处理。

## 8. 结束测试

1. 患者页点「确认无误」或直接关闭标签页，让数字人会话下线。这样也不会挡住「重点」判断。
2. 需要看「重点」时，等它出现后再关闭医生工作台。医生工作台不影响判断。
3. 关闭所有 `127.0.0.1` 页面，回到 SSH 窗口按 `Ctrl+C` 结束隧道。
4. **留在 Spark 上的数据**：只有文字，不上传云端，也不进仓库。
   - 问诊文字记录：患者原话、助手回复、小结，文件仅属主可读写；
   - 预问诊 agent 在本机工作区保存的草稿和两版记录；
   - 「重点」判断结果；
   - 开了摄像头观察时：关键点数值（`~/livetalking-logs/observations/<会话>.frames.jsonl`，只有数值、没有图像）和统计结果 `<会话>.observe.json`；
   - 数字人运行日志：目前会记下每轮文字，正式试用前需关闭或脱敏。

   原始录音只在内存中用于识别，不落盘；摄像头画面只在您的浏览器里处理，不录像、不上传。需要删除测试记录时，请联系负责人。详见 [`safety-and-privacy.md`](safety-and-privacy.md)。
